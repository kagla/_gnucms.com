# 회원 탈퇴와 로그인 이력 정책

## 결정

로그인 이력은 성공과 실패를 구분해 계속 누적한다. 단기 잠금 계산용 `password_attempts`와 달리
성공 시 지우지 않는다. 관리자는 로그인 기록 화면에서 전체 이력을 페이지 단위로 확인하고,
회원이나 IP를 선택해 해당 기록만 조회할 수 있다. 회원 수정 화면에서는 최근 20건을 확인한다.

`login_events`에는 회원 ID(알 수 있을 때), 로그인 식별자, 로그인 방식, 성공/실패, 접속 IP,
User-Agent, 발생 시각을 저장한다. 회원가입 당시 IP는 `users.registered_ip`, 탈퇴 IP와 시각은
`users.withdrawn_ip`, `users.withdrawn_at`에 별도로 보존한다.

## 탈퇴 확인

- 비밀번호 회원: 현재 비밀번호를 다시 확인한다.
- 소셜 전용 회원: 연결된 Google·네이버·카카오 계정으로 5분 유효 재인증을 한다.
- 마지막 활성 관리자 한 명은 탈퇴할 수 없다.
- 탈퇴는 되돌리지 않으며 세션 세대를 올리고 현재 세션을 종료한다.

## 탈퇴 시 데이터 처리

- 회원 상태를 `withdrawn`으로 바꾸고 이메일, 표시 이름, 비밀번호를 비식별 값으로 교체한다.
- 소셜 신원, 인증 토큰, 동의 상태와 개인 알림은 삭제한다.
- 글과 댓글은 보존하되 작성자 이름을 `탈퇴한 회원`으로 바꾸고 작성 IP를 비운다.
- 과거 로그인 이력은 조사 가능성을 위해 보존한다. 다만 이메일 같은 로그인 식별자는 비운다.
- 가입 IP, 로그인 당시 IP·방식·결과·시각, 탈퇴 IP·시각은 보존한다.

## 재사용 규칙

탈퇴로 해제된 이메일과 `(provider, provider_uid)`는 새 회원이 다시 사용할 수 있다. 이는 과거
계정 복구가 아니라 신규 가입이며, 새 회원 ID에 과거 글·댓글·동의·로그인 이력을 연결하지 않는다.
차단 상태인 기존 계정은 탈퇴가 아니므로 이메일과 소셜 신원을 계속 점유한다.

## 운영 참고

로그인 이력은 자동 삭제하지 않는다. 관리자는 로그인 기록 화면에서 기준 날짜 이전의 기록을
수동으로 일괄 삭제할 수 있으며, 선택한 날짜 00시의 기록은 삭제 대상에 포함하지 않는다.
`created_at`, `client_ip`, `(user_id, id)` 인덱스로 조회하고, 실제 보유 기간을 변경하려면 먼저
개인정보 처리방침과 운영 감사 요구를 함께 정한다.
