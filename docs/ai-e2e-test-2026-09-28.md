# AI 사용자 여정 테스트 결과 (2026-09-28)

## 범위와 환경

- 대상 코드: `edfa971` (`feat: complete shop payment and order management flows`)
- 방법: Chrome/Puppeteer로 설치, 관리자 설정, 회원 행동, 주문 처리를 실제 화면에서 진행했다. 결과 화면과 테스트 DB의 상태를 함께 확인했다.
- 환경: PHP 8.4.1, 로컬 웹 서버, **격리된 MySQL 테스트 DB**, 별도 애플리케이션 복사본. 기존 `config/config.php`, 운영 DB 및 기존 `storage/` 데이터는 사용하지 않았다.
- 이메일 인증은 로컬 발송 캡처로 확인했다. 주소 검색은 외부 우편번호 SDK 응답을 브라우저에서 모의했다. 무통장입금 계좌와 토스페이먼츠 인증 정보는 테스트용으로 설정했다. 실제 송금이나 실결제는 발생하지 않았다.
- 테스트 데이터: 관리자 1명, 이메일 인증 회원 1명, 게시판 1개, 게시글·댓글 각 1개, 2단계 상품 분류, 상품 1개, 무통장 주문 3건. 카드 결제창 취소는 주문을 만들지 않았다.

## 자동 테스트 결과

### PHPUnit

전용 MySQL 테스트 DB에서 `./vendor/bin/phpunit --no-coverage`를 1회 실행했다.

| 항목 | 결과 |
| --- | --- |
| 전체 | **실패** — 1,355 tests / 7,823 assertions / 64 errors / 26 failures / 1 warning |
| 실행 시간 | 40분 14.646초 |
| 주요 오류 | 53건은 테스트가 현재 없는 `GnuCms\Payment\Settings::enable()` 호출, 8건은 회원 ID가 필수인 `Orders::place()`에 `null` 전달, 2건은 삭제된 `guest_password` 컬럼 사용, 1건은 값 검증 예외 |
| 주요 실패 | 스키마 판 번호·테이블 수 기대치 불일치, 회원 전용 주문으로 바뀐 뒤에도 비회원 주문을 기대하는 테스트, 결제 설정·장바구니·주문서 HTML 기대치 불일치 |

예를 들어 [GatewayTest.php](../tests/Payment/GatewayTest.php), [CommerceTest.php](../tests/Shop/CommerceTest.php), [ShopCommerceTest.php](../tests/Web/ShopCommerceTest.php)는 현재 인터페이스와 맞지 않는 기대를 포함한다. `Settings::enable()`과 비회원 `Orders::place()` 관련 기대는 이번 커밋 전 코드에서도 성립하지 않았다. 다만 26개 assertion 실패와 나머지 오류를 모두 오래된 테스트 탓으로 단정할 수는 없다. **전체 테스트가 빨간 상태이므로 회귀 검증 신뢰도를 회복하려면 테스트를 현행 정책에 맞춰 갱신한 뒤 재실행해야 한다.**

### 브라우저 픽스처

`tests/Browser/*.cjs` 9개를 Chrome으로 실행했다.

| 결과 | 픽스처 |
| --- | --- |
| 통과 (5) | `EditorAssets`, `Header`, `PayProReturn`, `ShopAdminOptions`, `ShopPostcode` |
| 실패 (4) | `ExtensionAdmin`: JS 파싱 오류 `Unexpected token '<'`; `ShopBanner`: 360px 밝은 테마 폭 assertion; `ShopCart`: 현재 화면에 없는 `.yc-cart-toolbar strong` 선택자; `ShopOptions`: 추가옵션 감소 버튼 비활성 기대 불일치 |

`ShopBanner` 픽스처 실패와 달리 실제 관리자 설정 화면의 360px 뷰포트에서는 문서 가로 스크롤이 관찰되지 않았다. 픽스처의 모의 화면과 실제 화면 차이를 먼저 확인해야 한다. 다른 세 실패도 픽스처 또는 제품 동작의 문제인지 분리 조사해야 한다.

## 남은 검증과 권장 순서

1. 자동 테스트의 API·스키마·회원 주문 정책 기대치를 현행 구현에 맞춰 갱신하고, 위 4개 브라우저 픽스처의 실패 원인을 분리한다.
2. PG별 샌드박스 승인·거절·타임아웃·전액 및 부분 환불을 각 결제사의 인증 수단으로 끝까지 검증한다. 이 문서의 토스 테스트창 진입은 승인 성공을 뜻하지 않는다.
3. 재고 동시 주문, 여러 옵션·추가옵션, 배송비 경계값, 관리자·회원 권한 교차 접근, 주문 취소 직후 콜백과 같은 조합을 별도 자동 시나리오로 검증한다.

격리 테스트 DB와 브라우저 임시 파일에는 계정 비밀번호·세션·메일 인증 링크가 포함될 수 있어 저장소에 추가하지 않았다. 기존 작업 트리의 `storage/tmp/` 미추적 파일은 건드리지 않았다.
