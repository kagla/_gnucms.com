# 자동 문자와 관리자 편집

관리자 설정 → 알림별 발송 규칙(`/admin/settings/notifications`)에서는 알림별로 보낼 항목을 메일·문자 두 체크박스로 선택하고 문구·템플릿 연결을 관리한다. 문자는 알림톡을 포함하며 실제 발송 방식은 알림·발송 설정(`/admin/settings/messaging`)의 네 가지 옵션을 따른다. 공통 설정과 알림별 선택이 모두 허용해야 보낸다. 사이트 내 알림은 항상 기록하며 사용자가 끌 수 없다. 이메일 기본 수신·수신거부는 기존 정책을 유지한다. 문자·알림톡에는 회원 수신거부 설정이 없다. 선택은 `notify.<event>.delivery_configured`, `.delivery_mail`, `.delivery_phone`에 저장한다. 새 선택을 저장하기 전에는 현재의 공통 설정을 따르는 동작을 유지하며, 이전 문구 편집 요청은 선택값을 덮지 않는다. 과거 개별 알림톡·문자 ON/OFF 값은 사용하지 않는다.

## 자동 발송 지점

알리고 계정·상세 설정의 **채널 불러오기**(`/admin/aligo/profiles`)는 계정에 등록된 모든 채널과 채널별 전체 템플릿을 함께 조회한다. 승인 여부와 무관하게 코드·이름·유형·상태·검수 상태를 표시하고, **본문·버튼 보기**를 누르면 템플릿 이름·코드와 본문·버튼 정보를 모달로 보여 준다. 닫기 버튼·배경 클릭·Escape 키로 닫는다. 채널마다 전체·승인 건수를 표시하며, 한 채널의 템플릿 조회 실패는 해당 채널에만 안내하고 나머지 목록은 유지한다. 채널이 없거나 템플릿이 없는 경우도 구분해 안내한다. 조회만으로 발신프로필키 저장·템플릿 사본 가져오기·사용 설정·예약 취소는 하지 않는다. 승인되고 중단되지 않은 템플릿의 실제 사용은 기존 템플릿 관리 화면에서 설정한다.

사이트 전체 채널 사용은 **설정 → 알림·발송**(`/admin/settings/messaging`)에서 사이트 내 알림·메일·알림톡/문자 세 항목으로 관리한다. 사이트 내 알림은 필수 표시이며, 메일은 사용 안 함·자체 서버·SMTP 선택 후 저장한다. SMTP 선택 시에만 서버·계정 입력란을 펼친다. 알림톡·문자는 사용 안 함·문자만·알림톡 후 문자·알림톡만 중 하나를 고르면 즉시 저장한다. 알림톡 후 문자는 먼저 알림톡을 보내고 실패하거나 사용할 수 없으면 문자로 보내며, 알림톡만은 문자 대체 없이 보낸다. 기존 alimtalk_enabled·sms_enabled 두 상태를 같은 트랜잭션으로 저장하고 꺼지는 채널의 예약은 취소를 시도한다. DB 구조는 변경하지 않는다. 현재 조합 안내는 저장 응답과 실패 후 실제 상태 재조회 결과에 맞춰 갱신한다. 알리고 계정 연결과 알림별 문구·템플릿 편집은 상세 화면 링크로 연결한다. 알림별로 선택한 항목에 공통 발송 방식이 적용된다. 채널 끄기의 예약 취소·부분 취소 안내와 기존 메일 비밀번호 보존을 유지한다. 공통 채널 스위치와 저장된 문구·템플릿은 변경하지 않는다.

| --- | --- | --- |
| 가입·비밀번호 재설정·변경 | 기존 회원 서비스의 해당 이벤트 | 기존 토큰·계정 흐름 유지 |
| 댓글·답글 | 댓글 저장 | 자기 자신 제외, 글·부모댓글 작성자 중복 제외 |

| 결제 완료 | PG 승인 또는 입금 확인 최초 저장 | 동일 결제 재통보 제외 |
| 상품 준비·배송 중·배송 완료·취소 | 상태 전이 성공 | 실패한 전이·동일 상태 제외. 상태 되돌리기는 발송하지 않음 |
| 환불 | 새 환불 원장 기록 | 같은 환불 키 재요청 제외, 부분 환불마다 해당 건 금액 사용 |
| 상품문의 답변 | 첫 답변 등록·내용 변경 | 동일 본문 저장·빈 답변 삭제 제외 |

필수 알림은 업무 데이터와 같은 거래에 기록한다. 외부 발송은 최외곽 거래가 커밋된 뒤에 시작한다. CSV 및 결제 내부 거래에서도 롤백되면 발송 콜백이 제거된다. 발송 실패가 성공한 업무 저장을 취소하지 않는다. 기존 요청당 외부 호출 시간 제한과 접수 결과 불명 재시도 방지 정책을 유지한다. 주문 접수 후 즉시 결제되는 주문은 서로 다른 두 이벤트이며, 관리자가 둘 다 켜면 두 안내가 발생한다. 환불 후 주문 취소도 별개 이벤트다.

가입·계정 알림은 활성 회원의 계정 휴대폰번호를 사용한다. 주문 알림은 회원·주문 소유권과 주문번호를 확인하고 주문서에 저장된 주문자 이름·휴대폰번호를 사용한다. 회원정보의 번호가 없어도 주문자 번호가 있으면 보낼 수 있으며, 주문자 번호가 없거나 휴대폰 형식이 아니면 전화 채널을 건너뛴다. 회원 번호나 배송지 수령인 번호로 대신하지 않는다. 이메일은 기존 회원 계정 주소와 수신 선호를 유지한다. 상품문의 알림에는 비공개 문의·답변 내용을 담지 않는다. 문자 링크와 알림함은 문의 소유권 확인 후 상품의 해당 문의 페이지로 안내한다.

## 이메일 편집과 수신 미리보기

모든 코어 알림의 편집 창에 이메일 제목·본문 입력란을 제공한다. 기존 `MailBodies`의 문구를 기본으로 표시하며, 전화 채널을 지원하지 않는 알림 카드에는 기본 또는 저장된 이메일 제목·본문을 직접 보여 준다. 전화 지원 카드에는 문자 문구와 이메일 제목을 함께 표시한다.

- 제목은 최대 200자, 본문은 최대 20,000자의 일반 텍스트다. 이벤트가 제공하는 `#{변수}`만 사용할 수 있으며 제목 또는 본문의 마지막 선택 위치에 변수 버튼으로 삽입한다. 알 수 없는 변수·잘못된 마커·빈 제목/본문·제목 줄바꿈·제어 문자는 서버에서 거절한다.
- 기본 이메일 문구 넣기와 저장된 이메일 문구로 되돌리기를 제공한다. 복원 버튼은 편집란만 바꾸며, 알림별 저장 버튼을 눌러야 적용된다. 기본값으로 저장하면 별도 고정 사본 대신 코어 기본 문구를 사용한다.
- 이메일 수신 내용 미리보기는 관리자 권한·CSRF를 확인한 POST에서 현재 입력 문구에 예시 값을 넣어 제목·본문을 보여 준다. 실제 발송과 같은 치환 경로를 쓰고, 미리보기 성공 후 별도 결과 모달을 연다. 메일·문자 공통 미리보기 버튼은 현재 편집 탭의 미리보기 경로로 제출하며 기본 예시 값을 사용한다. 설정 저장·SMTP 호출·실제 메일 발송·실제 인증/수신거부 토큰 발급은 하지 않는다. 메일 앱별 글꼴·링크 표시는 달라질 수 있다.
- 구독 알림의 미리보기에도 예시 수신거부 링크와 재수신 안내를 붙인다. 실제 발송의 서명된 수신거부 링크는 기존 `MailPreferences`가 본문 뒤에 자동 추가하며 관리자 문구 편집으로 제거할 수 없다. 직접 요청한 인증·계정 복구 메일에는 수신거부 안내를 붙이지 않는다.
- 비밀번호 재설정·이메일 인증·소셜 이메일 확인 본문에는 `#{링크}`와 `#{유효시간}`을 유지해야 한다. 미리보기에도 두 예시 값이 필요하다.
- 기존 `site_settings`에 `notify.<event>.mail_subject`와 `notify.<event>.mail_body`를 저장한다. 채널이 꺼져 있어도 문구를 보존하고 편집할 수 있다. 문구를 보내지 않은 기존 저장 요청은 이전 값을 보존한다. DB 구조·스키마 51·제품 버전은 변경하지 않는다. 이메일 전역 설정과 기본 수신/수신거부 정책을 적용한다.

## 문자 편집 화면

편집 창 상단에서 보낼 항목(메일·문자)을 선택하고 아래 하나의 편집 영역을 메일·문자 탭으로 전환한다. 선택한 채널이 하나면 탭 없이 해당 입력만 표시하며, 아무 항목도 선택하지 않으면 문구를 숨기고 선택 안내를 표시한다. 탭 전환과 체크 변경은 입력을 지우거나 비활성화하지 않으며 공통 저장 버튼으로 두 채널의 수정 문구와 발송 선택을 함께 저장한다. 오류·미리보기 응답에서 현재 탭을 유지하고 오류가 있는 채널은 선택이 꺼져 있어도 표시한다. 키보드 좌우 화살표·Home·End로 탭을 전환할 수 있다.

메일은 제목·본문, 문자는 본문을 먼저 보여 준다. 변수·기본문구 복원과 LMS 제목은 접힌 상세 항목에서 수정한다. 알림톡 템플릿 선택·변수 연결·관련 안내는 문자 탭 안에서 공통 방식이 알림톡 후 문자·알림톡만일 때만 표시한다. 문자만·사용 안 함에서는 템플릿 입력을 제출하지 않으며 기존 연결을 보존한다. 발송 시점·수신 대상은 접힌 공통 항목이다. 메일·문자 예시 값 입력란은 제공하지 않으며 하단 공통 미리보기 버튼으로 기본 예시가 치환된 결과를 별도 모달에서 확인한다. 문자 결과에는 SMS/LMS 여부·길이를 표시한다. 닫기·배경 클릭·Escape로 편집 창으로 돌아오며 입력한 문구와 선택을 유지한다. 자바스크립트를 사용할 수 없으면 두 편집 영역과 별도 문자 미리보기 버튼·폼 안 결과를 제공한다. 이메일 전용 이벤트는 메일 입력과 선택만 제공하며 필수 알림함 선택·배지는 표시하지 않는다.

알림별 발송 규칙은 가입 완료·이메일 인증·가입 시도·소셜 로그인 이메일 확인, 비밀번호 재설정·변경, 댓글·답글, 주문 접수·결제·상품 준비·배송 중·배송 완료·취소·환불, 상품문의 답변 순으로 표시한다. 표시 순서만 정하며 이벤트 키·발송 시점·저장된 채널 선택은 유지한다.

- 알림 목록은 입력 박스 크기의 문자 문구를 항상 보여 주는 카드 그리드다. 하단에는 이메일 사용·알림톡/문자 발송 방식과 연결 확인 배지를 표시하며, 필수 알림함과 미사용 채널 배지는 생략한다. 문구 영역은 스크롤·선택·복사할 수 있으며 편집을 누르면 상세 설정을 연다.
- 알림 검색, 문자 가능한 이벤트 필터, 발송 시점·수신 대상 설명과 이벤트별 이력 링크.
- `회원`으로 가입 완료·가입 시도·이메일 인증·소셜 로그인 이메일 확인·비밀번호 재설정·비밀번호 변경 알림을 함께 찾는다. `비밀번호 찾기`, `비번 찾기` 같은 표현도 지원하며, 띄어쓰기 없이 입력하거나 `회원 비밀번호 찾기`처럼 여러 검색어를 조합할 수 있다. 제목·문자 문구·채널 배지 검색과 문자 가능 필터는 함께 적용한다.
- 고정 LMS 제목(선택, EUC-KR 44바이트), 문자 본문(2,000바이트), 이벤트별 기본 문구와 저장 문구 복원.
- 변수 버튼은 커서 위치에 삽입한다. 배송 이벤트는 택배사·운송장번호·배송정보 변수를 추가 제공한다. 배송정보가 비어 있으면 주문 조회에서 확인하도록 치환한다.
- 편집 중 바이트 수는 추정값이다. 미리보기 버튼은 관리자 권한과 CSRF를 확인하고 서버의 `MessageText`로 예시 치환·인코딩·정확한 바이트·SMS/LMS 분류를 검증한다. 알리고 호출·설정 저장·과금은 하지 않는다. 실제 발송 이력은 알리고의 전송중·대기 상태를 접수 대기로 유지하고 재조회하며 발송완료·전송성공 등의 최종 성공과 명시적인 실패를 구분한다. 같은 판정은 알림톡 대체문자에도 적용하며 불명확한 응답을 실패로 확정하거나 재발송하지 않는다. 기본 예시 값은 내부에서 사용하고 저장하지 않는다. 결과 모달을 닫거나 문구를 편집하면 지난 미리보기를 숨기며 다시 누르면 현재 입력으로 계산한다.
- API의 문자 본문·LMS 제목은 UTF-8을 유지하며 HTTP 폼에도 UTF-8 charset을 명시한다. EUC-KR로 요청 문구를 변환하지 않는다. EUC-KR 바이트 기준 검사는 단말기의 문자 길이·지원 글자 확인에만 사용한다.
- 실제 발송에서는 `Dispatch`가 수신자별 치환 후 다시 검사하고 90바이트를 넘으면 LMS로 분류한다. 이모지 등 EUC-KR에 없는 문자는 거절한다. 제목에는 변수를 허용하지 않는다.
- 문자·알림톡을 함께 켜면 기존 알림톡 우선·실패 시 문자 대체 정책을 따른다. 알림별 문자를 선택하고 공통 문자 발송 방식이 허용하면 전화 지원 이벤트에서 보낸다. 저장 문구가 없거나 비어 있으면 `Events`의 기본 문구를 사용한다. 알림톡은 연결된 사용 중 승인 템플릿이 있어야 보내며, 미연결·승인 대기 중에도 이메일·문자 문구는 저장할 수 있다. 템플릿 변수는 같은 이름을 자동 연결하고 고객명·회원명은 이름, 회사명·서비스명은 사이트명에 연결한다. 기존 사용자 지정 연결은 유지하며 자동 연결할 수 없는 변수만 직접 고른다.

발송 이력 목록은 가로 스크롤 없이 화면 폭에 맞춘다. 요청·예약 시각, 알림, 채널·템플릿, 총·성공·실패·취소 건수, 상태·테스트 표시, 상세 링크를 여섯 열로 묶는다. 좁은 본문에서는 같은 정보를 카드로 전환하며, 긴 알림명·템플릿·상태는 자연스럽게 줄바꿈한다. 목록 필터와 페이지 이동은 유지한다.

## 직접 보내기

회원 수정·주문 상세·상품문의 관리에서 수신 회원을 선택한 발송 화면을 연다. 주문·문의에서는 해당 업무 값도 가져온다. 알림 편집 화면에서는 저장 문구를 가져올 수 있다. 예시 값이나 일회용 비밀은 자동으로 채우지 않는다. 이 화면은 미리보기·직접 발송·예약·중복 제출 방지·결과 이력을 제공하는 기존 AligoService 경로를 사용한다. 화면을 여는 것만으로 발송되지 않으며 관리자가 발송 버튼을 눌러야 접수된다. 직접 발송은 자동 알림과 별개인 관리자의 명시적 발송이며 전역 채널 스위치를 따른다.

## 스키마 51

`notifications.feedback_id BIGINT NULL`을 신규 설치 DDL과 멱등 마이그레이션에 추가한다. 기존 알림과 이메일 기본 수신 설정은 변경하지 않는다. `version.txt` 제품판은 별도로 유지한다.


## 알리고 반환 비용

알림톡 발송 API의 `info.unit`·`info.total`을 발송 접수 시점에 `message_jobs.provider_costs`에 묶음별 발송 ID, 성공·실패 접수 건수, 기록 시각과 함께 저장한다. 숫자는 최대 소수 여섯 자리 십진 문자열로 보관하고 합산은 정수로 한다. 발송 이력 목록의 발송 정보와 상세 화면은 반환 금액이 있을 때만 비용을 포인트 단위로 표시한다. 묶음 일부만 금액을 반환하면 그 합계에 일부 응답임을 표시한다.

문자 API는 현재 금액을 반환하지 않는다. 단가 설정·예상 금액·단가 미설정 안내는 만들지 않는다. 금액이 없거나 기존 이력인 경우 항목을 표시하지 않으며 0원으로 간주하지 않는다. 결과 조회 API에는 비용이 없어 과거 기록을 역산·보충하지 않는다. 반환 비용은 접수 당시 API 값이며, 실패 환불·예약 취소·대체문자의 최종 비용으로 재계산하지 않는다. 이후 정산은 별도의 실제 정산 자료와 대사해야 한다.

근거: https://smartsms.aligo.in/alimapi.html (`info` 전송 응답), https://smartsms.aligo.in/admin/api/spec.html (문자 응답).


## SMS 비용을 줄이는 기본 문구

가입·댓글·상품문의·주문 상태 기본 문구는 핵심 상태 위주로 간결하게 표시한다. 주문 문자에는 주문번호·상태·짧은 조회 주소를 넣고 이름·금액·운송장·환불 상세는 주문 화면과 메일에서 확인한다. 회원 복구 알림은 일회용 인증 링크와 유효시간을 유지한다.

SMS와 알림톡 대체문자의 링크는 같은 사이트의 `/s/orders`(본인 주문 목록), `/s/notice`(본인 알림함), `/s/password`(비밀번호 찾기)를 사용한다. 고정 목적지로만 이동하고, 기존 로그인·주문 소유권 확인을 그대로 따른다. 주문 문자는 특정 주문번호를 본문에 표시하고 조회 링크는 주문 목록으로 연결한다. 외부 단축 URL 서비스와 공개 임의 URL 등록은 사용하지 않는다. 메일·승인된 알림톡 링크와 본문은 유지한다.

예전 기본 문구와 정확히 같은 저장값만 배포 시 새 기본 문구로 변경하고 사용자 편집 문구는 보존한다. 치환된 실제 본문의 EUC-KR 90바이트 이하면 SMS, 초과하면 LMS로 처리하는 기존 분류를 유지한다. 긴 사이트명·편집 문구·인증 링크를 억지로 자르거나 여러 SMS로 나누어 보내지 않는다.

문자용 주소는 목적지를 명확하게 드러내는 `/s/orders`, `/s/notice`, `/s/password`를 생성한다. 이미 발송한 문자의 `/s/o`, `/s/n`, `/s/p`도 동일한 화면으로 계속 연결한다. 기본 비밀번호 변경 문구는 긴 경로에서도 SMS 범위에 맞도록 간결하게 유지한다.

알림함 문자 주소는 `/s/notice`로 생성하며, 이전 `/s/notifications`도 호환 경로로 계속 연결한다.
