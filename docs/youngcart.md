# 쇼핑몰(영카트 모듈) 운영 안내

영카트5의 기능을 GNUCMS 확장 모듈로 다시 만든 쇼핑몰이다. 분류·상품·옵션·이미지·재고 관리와
반응형 종합 쇼핑몰 화면, 장바구니, 회원·비회원 주문 접수·조회·취소, 관리자 주문 처리를 제공한다.
온라인 결제(PG)는 아직 연결하지 않았다. 주문 접수 후 결제·배송 안내는 판매자가 별도로 진행한다.

## 주소와 패키지

| 항목 | 값 |
|---|---|
| 패키지 | `modules/youngcart` (작은 쇼핑몰이 `modules/shop`을 쓰는 동안 이 폴더를 유지한다) |
| 사용자 주소 | `/shop` — 메인 `/shop`, 분류 `/shop/list?ca=코드`, 유형 `/shop/type?t=hit|recommend|new|popular|discount`, 검색 `/shop/search?q=`, 상세 `/shop/item?id=상품코드` 또는 `?slug=`, 이미지 `/shop/image`, 장바구니 `/shop/cart`, 주문서 `/shop/checkout`, 주문 조회 `/shop/orders`, 주문 상세 `/shop/order?number=주문번호` |
| 관리자 주소 | `/admin/shop` 현황, `/admin/shop/settings`, `/admin/shop/categories`, `/admin/shop/products`와 `new`·`edit`·`types`·`stock`·`option-stock`, 주문 목록 `/admin/shop/orders`, 주문 상세 `/admin/shop/orders/detail?id=번호` |
| 별칭 | 없음. 설명 파일의 `aliases: false`로 `/modules/youngcart/…` 주소를 만들지 않는다 |
| 테이블 | `yc_settings`, `yc_categories`, `yc_products`, `yc_product_categories`, `yc_product_images`, `yc_option_groups`, `yc_options`, `yc_product_relations`, `yc_stock_log`, `yc_orders`, `yc_order_items`, `yc_order_history` (모듈 스키마 2판) |

작은 쇼핑몰(`modules/shop`)도 `/shop`을 기본 주소로 쓰므로 둘 중 하나만 켤 수 있다. 둘 다 켜면
나중에 등록되는 패키지가 "기본 주소가 다른 경로와 겹칩니다" 오류로 실행되지 않는다.

## 설치

1. 관리자 → 모듈에서 **쇼핑몰**을 켜고 저장한다.
2. `/admin/shop`에서 **데이터 설치**를 누른다. GET 조회만으로는 테이블을 만들지 않는다.
   SQLite는 설치 전에 `storage/backups/extensions/`에 자동 백업을 남긴다.
3. `/admin/shop/settings`에서 메인 블록·목록 크기·이미지 크기·배송/교환 안내문, 기본 배송비·무료배송 기준·주문 접수 안내를 정한다.
4. 분류를 만들고 상품을 등록한다. 사이트 상단 메뉴에 **쇼핑몰**이 자동으로 나타난다.

설치 전에는 모든 공개 주소가 "쇼핑몰을 준비 중입니다" 안내를 보여 준다.

### 기존 1판 설치에서 갱신

`/admin/shop`의 **데이터 설치**(또는 데이터 갱신)를 실행한다. 기존 카탈로그 테이블과 데이터를
그대로 두고 주문 테이블 3개와 인덱스를 추가한다. 중간 실패 후 다시 실행해도 안전하다.
등록된 주문 테이블은 GNUCMS의 확장 데이터 백업·복원에도 포함된다. 코어 DB 판 번호와 제품
`version.txt`는 이 변경으로 올리지 않는다. 갱신 전에는 공개 쇼핑몰이 준비 중 화면을 보여 준다.
기존 관리자 재고·일괄 편집 템플릿을 재정의했다면 아래의 `original_stock` 필드도 반영한다.

## 분류

- 코드는 단계당 2자, 최대 5단계다. 새 분류 폼이 형제 코드의 다음 값(`10`, `20`, … `z0`)을 제안하며
  직접 입력할 수도 있다. 생성 후에는 바꿀 수 없다.
- 목록은 요청한 분류 코드로 시작하는 모든 활성 하위 분류의 상품을 보여 준다. 상품의 대표 분류와
  추가 분류(최대 2개) 어느 쪽에 연결되어도 나온다.
- 판매가능을 끄면 목록·검색·상세에서 숨겨진다. 관리자는 상세를 미리보기로 열 수 있다.
- 하위 분류나 연결된 상품이 있으면 삭제할 수 없다.
- 수정 화면의 **하위 분류에 적용**은 판매·쿠폰·목록 크기·이미지 크기를 하위 분류에 함께 반영한다.

## 상품

- 코드는 영문·숫자·`-`·`_` 1~20자이며 생성 후 바꿀 수 없다. 폼은 현재 시각 10자리를 제안한다.
- 판매가격이 표시 가격이다. 시중가격은 0이 아닐 때만 취소선으로 보인다. 전화문의를 켜면 가격 대신
  문구를 보여 주고 구매 UI를 숨긴다.
- 포인트 설정은 정액, 판매가 %, 구매가 %(선택옵션 차액 포함) 중 하나이며 % 방식은 0~99다. 아직 실제 적립은 하지 않으므로 공개 구매 화면에는 혜택으로 표시하지 않는다.
- 배송비 유형은 상점 기본·무료·조건부 무료·유료·수량별이다. 장바구니와 주문서에서 실제 금액을 계산한다.
- 품절은 수동 품절 표시이거나, 선택옵션이 있으면 사용 중인 조합의 재고가 모두 0일 때, 없으면 상품 재고가 0일 때다.
- 두 관리자가 같은 상품을 동시에 수정하면 나중 저장이 "다른 관리자가 먼저 저장했습니다" 오류로 거절된다.
  새로고침 후 다시 입력한다.
- 저장 폼의 **일괄 적용** 체크와 적용 범위를 함께 쓰면 유형·판매·포인트·배송비 등을 같은 대표 분류
  또는 전체 상품에 반영한다.

### 옵션

- 선택옵션은 그룹 최대 3개, 그룹당 값 20개, 조합 1,000개까지다. 그룹 이름과 쉼표 구분 값을 입력하고
  **조합 생성**을 누른 뒤 조합별 차액·재고를 입력한다. 차액은 판매가에 더하는 값이며 합은 0원 이상이어야 한다.
- 추가옵션은 그룹명·항목명·절대가·재고를 행으로 입력한다.
- 저장은 조합 키 기준으로 갱신하므로 기존 조합의 재고가 유지된다. 제출하지 않은 조합은 삭제된다.
- 재고 변경은 `yc_stock_log`에 남는다. 주문 접수 시 재고가 차감되고, 취소 시 한 번만 복원된다.
- 처리 중인 주문(주문 접수·상품 준비)에 포함된 옵션은 삭제할 수 없다. 판매를 중지하려면 사용 여부를 끈다.

### 이미지

- 상품당 10장. JPG·PNG·WebP·GIF, 8,000px 이하, 용량은 사이트 설정의 첨부 용량을 따른다.
- 파일은 `uploads.dir/youngcart/{상품 id}/`에, 축소본은 `storage/cache/youngcart/`에 저장한다.
- 첫 이미지가 대표 이미지다. 수정 화면에서 순서와 삭제를 지정한다.

## 화면 재정의

테마의 `extensions/youngcart/` 아래에 같은 이름의 템플릿을 두면 조각 단위로 재정의된다.
정적 자산은 `www/themes/{테마}/youngcart.css`, `youngcart.js`, `youngcart-admin.css`, `youngcart-admin.js`이며 테마에 없으면 기본 테마 파일을 쓴다.

- 공개 화면은 GNUCMS 공통 레이아웃 위에 검색·쇼핑 메뉴·카테고리 바로가기·프로모션·상품 그리드를 구성한다.
  오늘의집의 쇼핑 탐색 구조를 참고하되 독립적인 코럴 포인트를 사용한다. 기본 테마의 밝기·다크 모드를 따른다.
  홈 프로모션 이미지는 실제 등록된 상품의 이미지를 사용하며, 고정 샘플 상품이나 외부 이미지 요청을 추가하지 않는다.
- 장바구니 `cart.php`, 주문서 `checkout.php`, 주문 조회 `orders.php`, 주문 상세 `order.php`와
  `_feedback.php`, `_steps.php`, `_totals.php`, `_order_detail.php`를 조각 단위로 바꿀 수 있다.
- `admin/extension.php`는 GNUCMS 공통 관리자 레이아웃·다크 모드·확장 CSS를 유지하면서
  쇼핑몰 CSS와 관리자 전용 CSS·JS를 한 번씩 추가한다. 전용 스타일은 `.yc-admin-page` 안에만 적용한다.
  재정의한 레이아웃에도 이 클래스와 자산을 반영한다. 별도 프런트엔드 빌드는 필요하지 않다.
- 관리자 머리글 `admin/_extension_header.php`, 메뉴 `admin/_nav.php`, 구역 이동 `admin/_form_nav.php`,
  고정 저장 영역 `admin/_save_bar.php`를 재정의할 수 있다. 저장 버튼은 반드시 해당 폼 안에 두거나
  HTML `form` 속성으로 연결한다. 상품 목록의 선택 삭제와 분류 행의 삭제 버튼도 각각 별도의 POST 폼에 연결된다.
- `_options.php`의 구매 폼은 `product_id`, `option_id`(옵션 없는 상품은 0), `quantity`,
  `extras[옵션 ID]`(추가 구성 수량), `action=cart|buy`, `csrf_token`을 `/shop/cart/add`로 POST한다.
  옵션 조합 하나를 선택해 담고, 다른 조합은 추가로 담는다. 자바스크립트 없이도 구매할 수 있다.
- 관리자 상품 목록·상품 재고·옵션 재고 폼에는 `rows[ID][original_stock]` 숨김 필드가 필요하다.
  화면 조회 당시 재고를 보내며, 주문 또는 다른 작업으로 재고가 바뀌었으면 저장을 거절한다.
  주문 내역이 있는 상품은 삭제할 수 없으므로 판매 여부를 끈다.

### 관리자 화면 사용

- 현황에는 상품 설정별 수량, 전체 기간의 현재 주문 상태, 최근 주문 최대 5건과 재고 통보 기준 이하의
  상품·옵션 최대 6건을 표시한다. 주문 수를 누르면 해당 상태의 주문 목록으로 이동한다.
  데이터 설치는 준비되지 않았을 때 표시하며, 설치 후에는 하단 **데이터 준비 완료 → 설치 정보**에서 갱신한다.
- 상품 목록에서는 상품명·가격·재고·판매 상태를 편집하고 **목록 변경사항 저장**을 누른다.
  저장은 현재 페이지의 모든 입력에 적용되고, 체크박스는 **선택 삭제**에만 쓰인다.
  분류 삭제는 각 행에서 처리하며, 상품 복사는 목록 아래 접힌 영역에 있다.
- 상품·분류 등록과 설정에는 구역별 바로가기와 하단 고정 저장 버튼이 있다. HTML·여분필드·상품 일괄 적용 범위는
  펼쳐서 입력한다. 자바스크립트 없이도 구역 이동·펼치기·저장이 가능하다.
  자바스크립트를 사용할 때는 미저장 변경 안내, 선택 개수, 오류 입력칸 안내를 추가한다.
- 주문 목록의 상태 메뉴는 입력한 검색어를 유지한다. 주문 상세에서는 고객·배송 정보, 금액, 처리 이력을 함께 확인한다.
- 모바일에서 주문 목록은 카드형으로, 편집할 열이 많은 상품·분류·재고 표는 내부 가로 스크롤로 표시한다.

## 장바구니와 주문

- 장바구니는 브라우저의 GNUCMS 세션에 저장되며 기기 간 동기화하지 않는다. 세션이 끝나면 장바구니도 사라진다.
  상품·옵션 ID와 수량만 저장하고 가격·옵션 차액·판매 상태·재고를 서버에서 다시 조회한다.
- 상품 수량은 최대 9,999개, 장바구니는 최대 100개 항목이다. 상품별 최소·최대 구매수량은 모든
  선택옵션의 본품 수량을 합산해 검증한다. 최소수량은 주문 시 검사하며 추가옵션은 본품 없이 주문할 수 없다.
- 장바구니에서 수량을 바꾸고 **수량 변경 저장**을 누른다. 0개로 저장하거나 삭제 버튼을 누르면 제거된다.
  본품을 모두 지우면 해당 상품의 추가옵션도 제거된다.
- **바로 주문하기**는 별도 주문서를 열며 기존 장바구니는 유지한다.
- 주문자는 이름·이메일·연락처, 수령인·연락처·우편번호(국내 5자리)·주소를 입력한다.
  상세주소·배송 요청사항은 선택이다. 비회원은 조회 비밀번호(8~72바이트)를 설정한다.
  비밀번호는 해시만 저장하고 폼에 재출력하지 않는다.
- 주문 내용과 배송 정보 제공을 확인한 후 **주문 접수**를 누른다. 온라인 결제는 진행되지 않는다.
  같은 주문서를 여러 번 제출해도 주문과 재고 차감은 한 번만 발생한다.
- 주문서를 연 뒤 상품·옵션·배송비·주문 안내가 바뀌면 최신 내용을 다시 확인하도록 안내한다.
  주문 접수 시 상품·옵션 재고를 하나의 트랜잭션에서 차감하므로 일부 상품만 접수되지 않는다.
  재고 차감은 예약 성격이며 주문 접수 자체가 입금 확인을 의미하지 않는다.
- 접수된 주문은 DB에 저장되므로 장바구니 세션이 끝나도 남는다. 회원은 로그인 후 자신의 주문을,
  비회원은 주문번호·이메일·비밀번호로 조회한다. 비회원 조회는 IP별 10분에 5회 실패 시 제한된다.
  주문 접수 시도는 일반 이용자 기준 10분에 20회로 제한한다.
- 구매자는 **주문 접수** 상태에서 주문 전체를 취소할 수 있다. 취소는 재고를 한 번만 복원한다.
  부분 취소·환불 및 주문 변경은 아직 지원하지 않는다.

### 배송비 계산

| 배송 유형 | 계산 |
|---|---|
| 상점 기본 | 같은 선불/착불 방식의 기본배송 상품을 묶어 기본 배송비를 한 번 적용. 해당 묶음의 상품·옵션 금액 합계로 무료 기준을 검사 |
| 무료 | 0원 |
| 조건부 무료 | 해당 상품의 선택·추가옵션 포함 금액 합계가 무료 기준 이상이면 0원, 아니면 지정 배송비 |
| 유료 | 해당 상품에 배송비 한 번 적용 |
| 수량별 | 본품 수량을 지정 수량으로 나눈 뒤 올림한 횟수 × 배송비. 추가옵션 수량은 제외 |

기본 배송비와 무료 기준의 초기값은 0이다. 무료 기준 0은 금액에 따른 무료배송을 적용하지 않는다.
선불은 주문 금액에 포함하고, 착불은 수령 시 별도 금액으로 표시한다. 상품이 선불·착불 선택을
허용하면 주문서에서 선택한 뒤 **배송비 반영하기**를 누른다. 이때 보안상 비회원 비밀번호를 다시
입력한다. 도서산간 추가비·해외 배송은 지원하지 않는다.

### 관리자 주문 처리

`/admin/shop/orders`에서 상태별 또는 주문번호·주문자 검색으로 찾고 상세 화면에서 처리한다.
주문 현황 카드에서도 해당 상태 목록으로 바로 이동할 수 있다.

| 현재 상태 | 다음 상태 |
|---|---|
| 주문 접수 | 상품 준비, 주문 취소 |
| 상품 준비 | 배송 중(택배사·운송장 필수), 주문 취소 |
| 배송 중 | 배송 완료 |
| 배송 완료·주문 취소 | 변경 불가 |

이력에는 처리자·시각·상태·관리자 메모가 남는다. 관리자 메모는 구매자에게 공개하지 않는다.
배송 완료 때 본품의 판매수량이 증가한다. 자동 입금 확인, 자동 취소, 주문 이메일·문자 발송은
아직 없으므로 접수 주문을 관리자가 주기적으로 확인해야 한다. 접수 대기 주문은 취소할 때까지
재고를 점유한다. 장바구니에 담는 시점에는 재고를 점유하지 않는다.
