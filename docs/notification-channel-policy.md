# 알림 채널과 이메일 수신거부

사이트 내 알림은 댓글·답글, 상품 준비·배송 중·배송 완료, 가입 완료와 비밀번호 변경에 항상 기록한다. 관리자와 회원 모두 이를 끌 수 없다. 자기 댓글은 자신에게 보내지 않으며 차단·탈퇴 회원에게 알림을 보내지 않는 기존 대상 규칙을 유지한다. 이메일 인증·비밀번호 재설정·가입 시도·소셜 이메일 확인은 로그인 전에 직접 요청한 계정 접근 메일이므로 알림함 대상과 구별한다.

관리자는 설정 → 알림·발송(`/admin/settings/messaging`)에서 이메일·알림톡·문자를 공통으로 선택한다. 각 알림과 주문 알림에서는 메일·문자 두 항목을 선택한다. 공통 설정과 알림별 선택이 모두 허용해야 발송한다. 문자는 공통 설정의 사용 안 함·문자만·알림톡 후 문자·알림톡만 옵션에 따라 발송한다. 이메일 전용 이벤트에는 문자 선택을 제공하지 않으며 서버에서도 거절한다. 문구·템플릿 연결은 선택과 별도로 유지한다. 템플릿 선택·변수 연결과 관련 안내는 알림톡 후 문자·알림톡만 모드에서만 표시하며, 문자만·사용 안 함에서는 숨긴 입력을 제출하지 않고 기존 연결을 보존한다. 새 선택을 저장하기 전에는 현재 공통 설정을 따르는 동작을 유지하고, 이전 개별 알림톡·문자 ON/OFF는 발송 판단에 쓰지 않는다. 문자 문구를 저장하지 않아도 기본 문구를 사용한다. 전화 채널은 알리고 연결·공통 채널 스위치·이벤트의 전화 지원 범위를 확인하며, 알림톡은 연결된 사용 중 승인 템플릿과 유효한 변수 연결도 확인한다. 알림톡 접수 실패 또는 템플릿 미연결 시 알림별 문자를 선택하고 공통 문자 설정이 허용하면 문자로 대체하며 같은 채널을 자동 재시도하지 않는다. 저장된 문구·템플릿 연결과 공통 채널 스위치는 그대로 유지한다.

회원의 이메일 알림은 기존 회원과 신규 회원 모두 기본 수신(`users.email_notifications = 1`)이다. 가입 화면에는 수신 여부를 묻지 않는다. 회원정보의 별도 이메일 알림 폼에서 수신거부·재수신을 저장하거나, 받은 알림 메일 하단의 수신거부 링크를 사용할 수 있다. 수신거부는 댓글·주문·가입 완료·비밀번호 변경 등의 이메일 알림에만 적용하며 직접 요청한 계정 인증·복구 메일은 계속 받을 수 있다. 문자·알림톡에는 회원 수신거부 설정을 추가하지 않는다. 가입·계정 알림의 전화 수신자는 회원정보의 휴대폰번호다. 주문 알림은 활성 회원과 주문 소유권·주문번호를 확인하고 주문서의 주문자 이름·휴대폰번호를 사용한다. 회원 번호가 없어도 주문자 번호가 있으면 발송하며, 유효한 주문자 휴대폰번호가 없으면 전화 발송을 건너뛰고 회원 번호·배송지 수령인 번호로 대체하지 않는다. 이메일 수신자는 기존 계정 주소를 유지한다.

메일 링크는 회원 ID·만료 시각·현재 이메일을 기존 auth.secret으로 HMAC 서명하고 1년간 유효하다. 회원 이메일 변경·탈퇴 후에는 기존 링크가 유효하지 않다. 링크는 수신거부 권한만 제공하며 로그인이나 재수신 설정 권한을 제공하지 않는다. GET은 확인 화면만 보여 주고 CSRF로 보호된 POST에서 수신거부한다. 회원정보 POST는 현재 로그인한 본인만 수정한다. 수신거부 화면은 no-store와 no-referrer를 사용하며 개인 이메일을 노출하지 않는다.

댓글·주문과 필수 알림함은 동일 트랜잭션에 저장한다. 필수 알림 저장에 실패하면 해당 거래도 취소한다. 외부 발송은 최외곽 거래 커밋 후에만 시작하며 배송 CSV 등 바깥 거래의 롤백에서는 발송하지 않는다. 외부 서버 장애는 이미 저장된 사이트 내 알림을 지우거나 성공한 거래를 실패로 응답하지 않는다. 외부 채널의 실제 도착은 전송 서버·알리고 및 수신기 상태에 따른다.

DB 판은 49에서 50으로 올리며 `users.email_notifications SMALLINT NOT NULL DEFAULT 1`을 신규 설치와 멱등 업그레이드에 추가한다. 운영 적용은 코드·users·notifications·site_settings의 비공개 백업 후 기존 선택값을 변경하지 않고 컬럼을 추가한다. 롤백은 코드와 스키마 도장만 되돌리고 확장 컬럼을 남긴다. 배포 후 변경된 회원 선호·댓글·주문·알림 데이터를 전체 DB 복원으로 덮어쓰지 않는다.
